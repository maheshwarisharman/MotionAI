# MotionAI Backend — Agent Instruction Manual

You are an expert backend engineer maintaining the **MotionAI** animation generator. This document outlines the architecture, standards, and constraints for this repository.

---

## 🚀 Project Overview
MotionAI is an AI-powered pipeline that transforms text prompts into professional infographic animations.
1. **Request:** User submits a prompt (e.g., "History of AI").
2. **Brain:** Gemini enriches the prompt and generates valid Remotion TSX code.
3. **Engine:** The backend bundles and renders that code into an MP4 file.
4. **Delivery:** The final video is uploaded to S3 and served via a pre-signed URL.

---

## 🛠 Tech Stack
- **Runtime:** Node.js 20+ (ESM)
- **Framework:** Express.js
- **LLM:** Google Gemini 1.5 Pro
- **Rendering:** Remotion (`@remotion/renderer`, `@remotion/bundler`)
- **Job Queue:** BullMQ + Redis
- **Storage:** AWS S3
- **Validation:** Zod (Environment & Requests)
- **Logging:** Winston (Structured JSON in production)

## 🏗 Key Components & Patterns

### 1. The Render Pipeline (12 Steps)
The `render.worker.ts` orchestrates the lifecycle of a job. **Maintain this progress mapping:**
- **5%:** Prompt Enrichment (Gemini Call 1)
- **20%:** Code Generation (Gemini Call 2)
- **35%:** JSX Sanitization
- **40%:** Bundling
- **40–90%:** MP4 Rendering (Mapped from Remotion 0-100)
- **90%:** S3 Upload & Cleanup
- **100%:** Completion

### 2. Security & Sanitization
**NEVER** render code without passing it through `src/utils/sanitize.ts`. It blocks dangerous imports (`fs`, `child_process`) and ensures the code is a valid Remotion component.

### 3. Performance Optimization
- **Symlink node_modules:** The `render.service.ts` symlinks the main `node_modules` into the temp directory instead of copying them. Do not change this to a copy operation; it will kill disk I/O and storage.
- **Concurrency:** Limited by `MAX_RENDER_CONCURRENT` in `.env`.

### 4. Realtime / WebSocket Architecture
- **Transport:** The backend exposes a WebSocket server at `/ws`, attached to the same HTTP server in `src/index.ts`.
- **Scale-safe fanout:** Realtime delivery uses Redis pub/sub via `src/services/realtime.service.ts`, so websocket events can fan out across multiple backend instances.
- **Subscription model:** Clients subscribe by `jobId` or `projectId` using JSON websocket messages such as `subscribe_job` and `subscribe_project`.
- **Initial snapshot:** Project subscribers receive a `project.snapshot` event containing the project, its message history, and the latest job status when available.
- **Lifecycle events:** The backend emits `render.job.queued`, `render.job.progress`, `render.job.completed`, `render.job.failed`, `project.updated`, and `project.message.created`.
- **Source of truth:** Queue/job state is mapped centrally in `src/services/job-status.service.ts` so HTTP polling and websocket updates stay consistent.
- **Worker integration:** `src/workers/render.worker.ts` publishes realtime progress for the existing render milestones, then emits completion/failure events after persistence.
- **Frontend use case:** This layer is used to deliver the final `downloadUrl` as soon as rendering completes and to stream updates for continuation/chat edits on existing projects.

## ✅ Dos
- **Use `GeminiService`:** Always use the built-in retry logic and sanitization feedback loop.
- **Strict Typing:** No `any`. Use `unknown` and narrow types or update `src/types/index.ts`.
- **Async/Await:** Avoid `.then()` chains. Use try/catch with `logger.error`.
- **Graceful Shutdown:** Ensure any new workers or connections are registered in the `shutdown` function in `index.ts`.
- **Env Validation:** Add all new environment variables to `src/config/env.ts` using Zod.

---

## ❌ Don'ts
- **No Direct S3 Access:** Use `storage.service.ts`.
- **No Local State:** The backend is designed to be horizontal. Use Redis for state.
- **No Plain Text Errors:** Never expose stack traces or raw AWS/Gemini errors to the API. Use the error mapping in `animation.controller.ts`.
- **No `npm install` in workers:** The environment is pre-built. Use the symlink strategy.
